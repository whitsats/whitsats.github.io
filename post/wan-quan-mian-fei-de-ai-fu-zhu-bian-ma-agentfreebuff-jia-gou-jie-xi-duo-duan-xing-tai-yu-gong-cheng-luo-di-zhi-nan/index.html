一、 核心定位与多智能体架构（简述）

Freebuff 并非单纯的模型套壳，其底层基于开源多智能体框架 CodebuffAI/codebuff，通过将复杂的编码任务拆解至不同的专精子智能体（如定位代码上下文的 file-picker、深度推演逻辑的 thinker、生成代码 Diff 的 code-editor 以及终端审查的 code-reviewer），实现端到端的自主代码变更。

    Subagents --> ModelPool["模型调度池<br/>(Luna / DeepSeek / MiMo / GLM)"]
    ModelPool --> Execution["本地文件改写 & 终端执行"]

二、 免费额度、模型梯度与美区虚拟网卡限制（核心必读）

许多开发者首次使用 Freebuff 时会发现只能使用单一的 MiMo 模型且 Session 次数极少，这是由于网络环境未满足全功能判定所致。深入理解其网络判定机制与模型梯度池是顺畅使用的前提。

2.1 网络环境关键技巧：开启美区虚拟网卡（TUN 模式）

Freebuff 内置严格的地域与代理流量检测逻辑，并划分了两种截然不同的运行模式：

运行模式 网络触发条件 开放模型池 额度与 Session 限制
Full Mode（全功能模式） 开启美区虚拟网卡（TUN 模式），接管终端全局流量 全部模型解锁：GPT-5.6 Luna、GLM 5.3 Flash、DeepSeek V4 Flash、MiMo 2.5 享有每日 5 次 Premium 独立 Session + 两个 Unlimited 无限模型
Limited Mode（受限模式） 未开启虚拟网卡、普通网页代理或非白名单地区直连 仅限单一 MiMo 2.5 模型，高端模型全部锁定不可选 Session 每日严重缩减（仅 3 次或更低）

[!IMPORTANT]
关键避坑指南（国内开发者必看）：
终端（CLI）发起的 HTTP/WebSocket 流量通常不经过浏览器常规代理插件。必须开启代理客户端的“虚拟网卡 / TUN 模式（美区节点）”，实现全系统流量接管，Freebuff 才能正确识别并激活完备的 Full Mode。

  • GPT-5.6 Luna：全能主力旗舰，具备高推理能力（Reasoning: high）并支持图像多模态输入，适用于复杂全栈重构与算法编写。

三、 Freebuff CLI 深度实战指南（核心操作）

Freebuff 的核心生产力形态是其命令行工具（CLI）。它直接内嵌在本地终端中，拥有读取本地代码、生成 Diff 并执行测试命令的完整权限。

3.1 环境准备与一键安装

Freebuff CLI 依赖 Node.js 环境（要求 Node.js 18 及以上版本）。

# 1. 检查本地 Node.js 版本
node -v   # 建议 >= v18.0.0

# 2. 全局安装 Freebuff CLI
npm install -g freebuff

# 3. 验证安装是否成功
freebuff --version

3.2 首次启动与身份认证

  1. 开启美区虚拟网卡（TUN 全局模式）；
  2. 进入本地待开发工程的根目录并启动：
    cd ~/my-project
freebuff
  3. 浏览器 OAuth 鉴权：终端首次运行时会输出授权链接并自动调起浏览器，使用 GitHub 或 Google 账号登录完成绑定即可。

3.3 核心指令与标准工程工作流

在实际项目演进中，严禁随意输入模糊提示词让 AI 大面积盲写。Freebuff 设计了一套标准的阶段式命令，保障代码修改安全可控：

sequenceDiagram
    autonumber
    actor Dev as 开发者
    participant CLI as Freebuff 终端
    participant Agent as 智能体集群
    participant Workspace as 本地代码库

    Dev->>CLI: 1. 执行 /interview (需求对齐)
    CLI->>Agent: 交互式澄清边界与入参规范
    Agent-->>Dev: 确认功能设计契约
    Dev->>CLI: 2. 执行 /plan (生成方案)
    CLI->>Agent: 定位受影响文件并生成执行计划
    Agent-->>Dev: 呈现涉及的文件路径与改动清单
    Dev->>CLI: 3. 确认执行修改 (Proceed)
    CLI->>Workspace: 应用代码变更并输出 Unified Diff
    Dev->>CLI: 4. 执行 /review (代码走查)
    CLI->>Agent: 审计潜在 Bug 与破坏性变更
    Agent-->>Dev: 输出审计结果与优化建议

Step 1: 需求对齐与契约澄清 (/interview)

在着手大功能前，输入 /interview 启动交互式采访模式。智能体会根据你的初步想法，反向提出关键技术决策问题（如：状态持久化方案、错误码规范、依赖包版本兼容等），确保开发边界清晰。

Step 2: 方案推演与实施规划 (/plan)

输入 /plan <具体改动目标>。此时 thinker 与 file-picker 智能体会通读相关代码，输出一份详细的实施规划文档，标明涉及的每一处文件与函数改动，但暂不修改磁盘文件，供开发者审阅。

Step 3: 代码自动实施与 Unified Diff 校验

在确认 Plan 方案可行后，输入确认指令。code-editor 智能体会生成精准的 Diff 补丁并落盘。终端会高亮展示修改差异（Green/Red 增删行），方便开发者直观比对。

Step 4: 代码质量走查与静态审计 (/review)

在功能完成后，输入 /review。智能体会自动比对本次会话的所有 git diff，检查是否存在未处理的异常分支、内存泄露隐患或命名规范问题。

3.4 CLI 常用快捷命令与高级技巧

常用命令 / 语法 功能描述 典型应用场景
/model 弹出模型选择面板，动态切换当前使用的底层大模型 复杂架构推演时切至 Luna/DeepSeek，普通小修切至 MiMo
/interview 启动需求澄清会话，明确功能契约与边界 复杂业务逻辑开发前的设计对齐
/plan 制定多文件修改的实施计划 大规模代码重构或新增独立模块
/review 针对当前代码变更进行静态质量与安全审计 提交 Pull Request 前的自检自查
/reset 清理当前会话上下文，重新开始新任务 切换至无关的独立任务，避免上下文污染
/compact 压缩当前长对话的历史上下文 遇到超长会话导致 Token 膨胀时保留关键摘要
/help 查看 CLI 完整内置指令帮助手册 快速查阅支持的操作语法
@<filename> 强制显式引用特定文件或目录至上下文 精确指定需要修改或参考的目标源码文件
